### `library/riscv-aia/src/register/stopei.rs` line 5

> [code-derivable] `stopei` is described as a "top external interrupt" reporting CSR, similar to `mtopi`. ### `library/riscv-aia/README.md` line 1

> [code-derivable] Could we avoid maintaining the same crate introduction independently in both `README.md` and `src/lib.rs`? The PR updates the specification version in both places, but they can drift. [fixed in final diff: `#![doc = include_str!("../README.md")]`]

### `library/riscv-aia/src/register/mtopi.rs` line 22

> [code-derivable] `MajorIid` allows IID 0, but `mtopi`, `stopi`, and `vstopi` still return `None` whenever the decoded IID is zero. `0x0000_0001` has IID 0 and IPRIO 1, so the CSR is nonzero and represents an interrupt. The absence check should be based on the complete masked CSR value. [fixed in final diff for `*topi`; the same defect remains in `mtopei`/`stopei`/`vstopei`]

### `library/riscv-aia/src/register/hviprio1.rs` line 99

> [code-derivable] Use clearer names for the byte helpers. `prio_byte` and `set_prio_byte` are somewhat ambiguous, and `i` does not indicate that it is a byte index rather than an interrupt number. [fixed in final diff: renamed `priority_at_byte_index`]

### `library/riscv-aia/src/register/sie.rs` line 14

> [code-derivable] The bounds assert is the right contract — but the same `bit()` helper on `Sie`/`Sip`/`Vsie`/`Vsip` kept the unguarded form, so the eight sibling APIs now disagree. [fixed in final diff: asserts added; `Sie`/`Sip` then dropped `bit()` entirely, which leaves a different inconsistency]
